# Skill: update-memory

Without auto-commit, cloud routines see nothing on the next run. This skill is the
contract that ties the whole system together.

## When to use
Every routine ends with this skill. No exceptions.

## Procedure

```python
from src.memory.writer import (
    overwrite, append, daily_snapshot, routine_commit
)

# 1. Overwrite state file (portfolio.md is the only "state" file — others are append-only)
overwrite("portfolio.md", portfolio_markdown)

# 2. Append to logs (only if there's actually new content)
if new_trades:
    append("trade_log.md", trades_markdown_block)

if new_research:
    append("research_log.md", research_markdown_block)

# 3. Append to today's daily snapshot
daily_snapshot(daily_section_markdown)

# 4. Update lessons.md ONLY if there's a genuine new lesson — most routines: skip this step.
if has_real_lesson:
    append("lessons.md", lesson_markdown)

# 5. Commit + push (atomic — single commit per routine)
success, output = routine_commit("01-pre-market")  # use the routine slug
if not success:
    # Don't crash the routine — log and notify
    print(f"WARN: git commit failed: {output}")
```

## Commit message format
Auto-generated by `routine_commit()`:
```
routine: <slug> @ <ISO UTC timestamp>
```
For exceptional commits (e.g. recovering from an error), use:
```
chore: <description> — Bull <ISO UTC timestamp>
```

## Anti-patterns
- DO NOT commit `src/`, `routines/`, or `CLAUDE.md` from a routine. Those are Robin's territory. Only `memory/` is bot-writable.
- DO NOT push to a feature branch. Cloud routines work on `main` directly.
- DO NOT write secrets into ANY memory file. Even by accident. Triple-check WhatsApp body, lessons, daily snapshots.
